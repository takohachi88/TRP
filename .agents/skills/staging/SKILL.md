---
name: staging
description: この会話で対応した変更を Git のステージに追加するときに使う。既存の変更が混在していても、今回の対応分を特定してステージする。
---

1. 会話上の作業記録と `git status --short`、`git diff`、`git diff --cached` を突き合わせる。今回追加した未追跡ファイルは内容も確認する。Git の状態だけで変更の帰属を判断しない。
2. ステージするファイルまたは差分と、特定できない箇所を示す。リポジトリの `AGENTS.md` に従い、対象について承認を得てから Git インデックスを更新する。対象がすでに承認済みの場合はその承認を使う。
3. ファイル全体が対象なら、リポジトリ直下で `git --literal-pathspecs add -- <対象パス>` を使う。同じファイルに別作業の変更が混在する場合は、対象部分だけをステージする。目的の差分を安全に分けられない箇所は保留する。既存のステージ済み差分は維持し、作業ファイルの編集、コミット、プッシュは対象外とする。
4. `git diff --cached` で実行前後の差分を確認し、今回追加した内容と保留した箇所を報告する。対象がすでにステージ済みなら、その旨を報告する。
